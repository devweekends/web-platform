Two IdeasDeploy vs release
Why the difference matters

Shipping code is not
the same as releasing

Deployment
Code is on servers
01A technical event your team controls.
02Can happen many times a day.
03Safe when the new code stays dormant.
Release
Users see it
01A product decision, switched on by a feature flag.
02Turn it on for a few users first.
03Turn it off without a new deploy.

StrategiesPick on purpose
Three ways to roll out

Rolling, blue-green
or canary

01
Rolling
Replace instances a few at a time. Built into most orchestrators. Rollback is slow.
Routine, low-risk changes
02
Blue-green
Run a full second environment, then switch traffic at once. Rollback is instant but costs double infrastructure.
Major releases, strict compliance
03
Canary
Send a small share of real traffic to the new version first. Catches production-only bugs. Needs strong metrics.
High-traffic systems, unknown risk

DatabasesExpand and contract
Zero-downtime migrations

Change the schema
in small steps

Old and new code run side by side during a deploy, so the database must work for both.

01
ExpandAdd the new column or table. Nothing reads it yet.
02
MigrateBackfill in batches and write to both. Switch reads when ready.
03
ContractRemove the old column only after no running code uses it.
04
Never in one stepNo column drops, no renames, no NOT NULL without a default.

What To CaptureThe baseline
Four signals

Errors from 0.1% to 0.5%
is a problem

Errors
4xx and 5xx, per endpoint
Latency
p50, p95, p99 and p999
Traffic
Requests per second
Resources
CPU, memory, disk, network

Also check dependency health: database latency, cache hit rate and external APIs. Do not deploy into a system that is already degraded.

ReliabilityThe SRE view
Decide how reliable is enough

Reliability is a
budget

Perfect uptime is not the goal. Agree on a target, measure it, and spend the margin deliberately.

01
SLIs, SLOs and error budgetsMeasure what users feel, set a target, and track how much failure you can still afford.
02
Retries with backoff and jitterRetry in a way that does not stampede a struggling service.
03
Timeouts, circuit breakers, bulkheadsStop one slow dependency from taking everything down.
04
Graceful degradationServe something useful when a part fails.
